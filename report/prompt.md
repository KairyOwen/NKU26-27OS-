## 一、提示词模板

> ⚠️ **待核对**：实验指导书 `lab0.5 / 3_prompt_structure.html`（"本实验的标准提示词结构"）给出了官方模板，
> 报告模板中出现的 `[RELY]`、`[SPECIFICATION]` 就是该结构中的段落名。
> **请打开指导书确认后，把官方模板粘贴到本节**，并按它改写下面的各条提示词。
> 下面给出的是与 `[RELY]` / `[SPECIFICATION]` 命名一致的**占位版本**。

````markdown
# [ROLE] 角色
你是一名正在实现 RISC-V 64 位最小可执行内核的操作系统开发者。

# [CONTEXT] 工程背景
- 项目：riscv64-ucore（教学用操作系统）
- 目标平台：QEMU `virt` 机器，`-bios default`（OpenSBI 固件）
- 内核链接基址：0x80200000，入口符号 `kern_entry`
- 工具链：riscv64-unknown-elf-gcc（-mcmodel=medany, -march/-mabi 默认 riscv64）

# [RELY] 依赖 / 可用的既有代码
<!-- 列出本次要修改/依赖的文件、函数签名、宏定义、已有的头文件等。
     信息不完整是 AI 跑偏的第一大原因，务必写全。 -->

# [SPECIFICATION] 需求规格
<!-- 要做什么，输入是什么，输出是什么 -->

# [CONSTRAINTS] 约束
<!-- 不允许引入标准库、不允许改动的文件、必须保持的调用约定等 -->

# [CRITERIA] 正确性判据
<!-- 什么样算正确（应观察到什么输出/行为），什么样算错误（反例） -->

# [VERIFICATION] 验证方式
<!-- 如何自证：编译命令、运行命令、期望输出、GDB 检查点 -->

# [OUTPUT] 输出要求
<!-- 只要函数实现？还是要 diff？要不要解释？ -->
````

## 三、禁止出现的提示词形式

- ❌「把这个问题搞定，不要问我任何问题，直到你搞定为止」
- ❌ 只说现象不说上下文（例如只写"板子不动"、"编译不过"）
- ❌ 让 AI 自己猜函数签名/宏定义 —— `[RELY]` 里必须写全
