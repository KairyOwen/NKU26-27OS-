## 三、B：刘梓涵，线程创建及初始化

### 修改范围

`kern/process/proc.c` 的 `LAB4 function2` 区域，实现以下六个函数：

```c
static struct proc_struct *alloc_proc(void);
void proc_init(void);
int kernel_thread(int (*fn)(void *), void *arg, uint32_t clone_flags);
int do_fork(uint32_t clone_flags, uintptr_t stack, struct trapframe *tf);
static void copy_thread(struct proc_struct *proc, uintptr_t esp, struct trapframe *tf);
static int copy_mm(uint32_t clone_flags, struct proc_struct *proc);
```

签名最终以实际框架和调用处为准，不改公共接口来绕过实现。

### 具体工作

1. `alloc_proc()` 分配并安全初始化 PCB，核对 state、pid、runs、kstack、need_resched、parent、mm、context、tf、pgdir、flags、name 和链表字段；分配失败返回 NULL。
2. `proc_init()` 初始化进程链表和 PID 哈希，建立 idleproc/current，复用启动内核栈并设置特殊 PID、状态和调度需求；创建并命名 initproc。
3. `kernel_thread()` 把线程函数及参数放入符合 `kernel_thread_entry` 约定的临时 trapframe，设置正确的特权返回状态，调用 do_fork。
4. `copy_thread()` 把 trapframe 放到新线程内核栈上，设置新线程返回值、栈和 context，使第一次切换走通 `forkret → forkrets → __trapret → kernel_thread_entry → fn(arg)`。
5. `do_fork()` 完成进程数限制、PCB/内核栈分配、copy_mm/copy_thread、父子关系、PID、哈希和进程链表登记、计数以及唤醒。登记与 PID 分配等共享状态更新遵循临界区约定。
6. 失败时按已获得资源逆序回收；未准备完整的线程不能提前登记为可运行，失败不能泄漏 PCB 或栈。
7. 当前 `copy_mm()` 按内核线程共享内核空间的阶段要求实现，不扩展成用户进程 fork，不伪称已完成用户地址空间复制。
8. 阅读 `kern/process/entry.S`、context/trapframe 定义和 forkrets，但仅在确有接口问题时协商修改现成汇编。

### 验收与交接

检查 PCB 初值、idle/init 身份、PID 唯一性、find_proc、进程登记、栈与帧位置、fork 返回值和失败清理。C 的调度缺失时不要求 initproc 已真正执行；最终创建与首次执行证据由 C 集成后补齐，B 配合定位。

## 四、C：李熔吉，调度与最终集成

### 修改范围

- `kern/process/proc.c` 的 `LAB4 function3`：`cpu_idle()`、`proc_run()`。
- `kern/schedule/sched.c` 的 `LAB4 function3`：`schedule()`。
- `kern/process/switch.S` 的 `LAB4 function3`：`switch_to()`。

文档有时写 switch.s，实际压缩包文件为大写 `switch.S`，以文件系统为准。

### 具体工作

1. `cpu_idle()` 在需要重新调度时调用 schedule，保持空闲线程作为无其他 runnable 线程时的兜底。
2. `schedule()` 在临界区清除当前 need_resched，沿进程链表选择下一个 `PROC_RUNNABLE` 线程，找不到则选 idleproc，按框架维护 runs 并调用 proc_run。
3. 当前非 idle 时从其后继开始循环查找，idle 时从链表头查找；跳过 sleeping/zombie。应解释实际的循环查找策略，不简单照抄“FIFO”标签，也不在没有时间片机制时声称实现了完整的时间片轮转。
4. `proc_run()` 处理目标与 current 相同的情况；需要切换时保存中断状态，更新 current，写入目标页表的 Sv39 satp，刷新 TLB，再调用 switch_to。
5. 不使用 `libs/riscv.h` 中 Sv32 遗留的 `lsatp()`；按 `enable_paging()` 的正确方式构造 `SATP_MODE_SV39 | (页表物理地址 >> 页移位)`，防止把物理地址当页号。
6. `switch_to()` 严格按 `struct context` 保存/恢复 ra、sp、s0～s11，共 14 个 RV64 寄存器槽位；它只负责现场迁移，不负责挑选线程。
7. 核对切换前后的中断状态，特别是首次线程从预制 trapframe 返回时的 SPP/SPIE/SIE。context 与完整 trapframe 的用途和保存范围不能混淆。
8. 保留 B 已完成的 function2，集成问题按模块交原负责人修复，C 再复验。

### 最终验收

1. 干净构建、启动，观察内存/页表/VMA 初始化和 idle→init 的首次切换。
2. 原始评分检查三个项目：`[Test PMM] PASS`、`[Test Process Create] PASS`、`[Test Schedule] PASS`，每项 10 分，合计 30 分。这是评分脚本的目标，不是已取得的成绩。
3. 调度检查还要求 initproc 的 PID/名称输出、`Hello world!!` 和结束问候。必须运行并保存实际日志。
4. 本包 `do_exit()` 当前为 `panic("process exit!!.")` 占位，未列为本次必做函数。线程函数返回可能进入此路径，不能不加区分地把任何 panic 都当作分配/调度失败，也不能把占位退出写成完整退出与资源回收。
5. 原始 grade 依赖 QEMU、GDB、readline 断点、bc 等；先核对工具名与 QEMU 4.1.1 路径。工具兼容问题与功能失败分别记录，不改通过条件或输出假 PASS。
6. 提供调度补充检查：无其他 runnable、跳过非 runnable、同线程不切换、上下文槽位一致。仅单次 idle→init 输出不能证明所有边界都已覆盖。
